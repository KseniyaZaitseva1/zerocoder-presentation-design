Новое понятие

MCP — протокол для AI-приложений

Model Context Protocol

Согласованные правила, по которым AI-приложение получает данные и вызывает внешние инструменты.

Протокол — правила обмена

Какие сообщения отправить и как понять ответ.

Сервер — программа-посредник

Предоставляет операции: например, найти страницу или создать файл.

Codex — приложение с агентом

Формулирует вызовы инструментов, затем использует полученный ответ.

Подключено — ещё не значит «умеет всё»

Есть инструмент?

Поиск документов не означает, что сервер умеет загружать изображения или создавать базы данных.

Есть права?

Чтение и запись могут быть разрешены отдельно. Аккаунт должен видеть выбранный объект.

Понятна задача?

Два направления подключения

Кто обращается к кому?

Внутри Yonote

Yonote → внешний MCP → другой сервис. В разделе /settings/mcp добавляем инструменты для работы из Yonote.

Из Codex в Yonote

Codex → MCP-сервер Yonote → страницы проекта. Для нашей практики нужен именно этот маршрут.

Адрес страницы настроек не является адресом MCP-сервера. В уроке подключаем сервер, который умеет читать и создавать страницы Yonote.

Схема настройки · пример

Подключение Yonote в Codex

[mcp_servers.yonote] command = "node" args = ["PATH_TO_MCP/yonote-mcp/dist/index.js", "--project", "your-workspace"] env_vars = ["YONOTE_API_TOKEN"]
Путь к программе

Замените пример на реальный путь после установки. dist/index.js появляется после сборки.

Название пространства

your-workspace — пространство эксперта. Студент указывает своё.

Токен отдельно

Задайте YONOTE_API_TOKEN в окружении Codex. Настройка передаёт имя переменной, а не секрет.

Как запускается и оплачивается?

Проверяем зависимости, условия сервиса, тариф и лимиты.

Как проверить и отключить?

Пробуем чтение. При необходимости выключаем сервер и отзываем его токен.

Руководство GitHub ↗

PAT — персональный токен

Секрет доступа от имени аккаунта. Создаём в GitHub и выдаём необходимые права.

Проверка

Перезапускаем Codex. Просим назвать подключённый аккаунт и прочитать тестовый репозиторий.

Техническая настройка

Адрес и секрет хранятся отдельно

[mcp_servers.github] url = "https://api.githubcopilot.com/mcp/" bearer_token_env_var = "GITHUB_PAT_TOKEN"
Где сохранить блок

В ~/.codex/config.toml. Добавляем к имеющимся настройкам.

Где хранить токен

В переменной окружения GITHUB_PAT_TOKEN, доступной Codex. В конфиге выше только её имя.

Не показываем секрет

Не вставляем в промпт, README и запись урока. Файл .env сам по себе ещё не передаёт токен приложению.
